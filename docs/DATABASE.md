# Database

PostgreSQL via Supabase. Migrations: `supabase/migrations/*.sql`. Seed: `supabase/seed.sql` (generated by `npm run db:seed-sql`).

## Migrations

| File | Contents |
|---|---|
| `20261009000001_schema.sql` | Enums, all tables, indexes, `updated_at` triggers |
| `20261009000002_rls_and_functions.sql` | Helper functions, signup trigger, child-limit trigger, `has_premium`, `export_family_data`, RLS on every table, storage bucket policies |
| `20261010000003_tracks_and_payments.sql` | `tracks` (age tracks, public read / editor write), `children.track_id`, `billing_provider += 'paymob'`, `payments` (one row per checkout; unique reference and provider transaction id; parents read own, service role writes), `subscriptions.cancel_at_period_end` / `payment_method` |

`users` is Supabase's `auth.users`. A trigger creates `parent_profiles` + a free `subscriptions` row on signup.

## Tables

**Family:** `parent_profiles`, `children` (nickname, age, age band, languages, interests, accessibility; pseudonymous `analytics_id`), `child_preferences`, `avatars`, `subscriptions`.

**Content (CMS source of truth):** `languages`, `interface_languages`, `curriculum_levels`, `skills`, `grammar_patterns`, `vocabulary` (concepts), `lexemes` (concept × language), `phrases`, `curriculum_units`, `characters`, `worlds`, `story_arcs`, `journeys` (authored episodes), `journey_scenes` (beats), `games`, `game_templates`, `rewards`, `achievements`, `books`, `songs`, `roleplays`, `avatar_items`, `companions`, `media_assets`, `content_translations`, `content_bundles` (immutable versioned releases with checksum).

**Learner (per child, per language):** `language_progress`, `learning_mastery` (12-dimension jsonb), `review_schedule`, `daily_sessions` (incl. the generated journey json), `activity_history`, `game_sessions`, `speech_attempts` (transcript + score only), `pronunciation_results`, `reading_progress`, `writing_progress`, `story_state`, `story_choices`, `companion_progress`, `reward_inventory` (incl. streak, visited worlds), `book_progress`, `creations`, `parent_reports`, `sync_operations`.

**Platform:** `notifications`, `feature_flags`, `experiments`, `experiment_assignments`, `admin_users` (roles: owner, editor, reviewer, translator, support, analyst), `audit_logs`, `analytics_events`.

## Row Level Security

- Every table has RLS **enabled and forced**.
- Parents: `parent_id = auth.uid()`; child tables use `owns_child(child_id)` (security definer).
- Subscriptions: parents can only **read**. Writes happen only through verified webhooks using the service role.
- Child limit enforced by trigger (`free` 2 · premium 3 · family 6), not just in UI.
- Content: anon/authenticated read **published** rows; editors/reviewers write. Drafts are invisible to families.
- Translations: editors, translators, reviewers.
- Analytics: inserts allowed only for the caller's own pseudonymous child ids or self; reads for analysts.
- Admin users, audit logs: admins only.
- Storage `content-media`: public read, editor write.

`tests/db/rls.test.ts` runs both migrations and the full seed in an embedded Postgres (PGlite) and verifies: family isolation (read and write), self-upgrade blocked, child-limit trigger, draft content hidden, admin-only writes, analytics isolation, export scoping, tracks readable/parent can set only their child's track, payments isolation and no client writes.

## Data export & deletion

`export_family_data()` returns the caller's whole family as JSON. Account deletion (`/api/account/delete`) deletes the auth user; `on delete cascade` removes all family data, and pseudonymous analytics are deleted explicitly.

## Applying

```bash
supabase link --project-ref <ref>
supabase db push                       # applies migrations
psql "$DATABASE_URL" -f supabase/seed.sql   # or paste into the SQL editor
```
Local: `supabase start && supabase db reset` (runs migrations + seed.sql).
